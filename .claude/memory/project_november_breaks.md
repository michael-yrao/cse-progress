Set by learner Aug 6, 2026. **Two ~1-week breaks in November 2026**, both **light-maintenance, not
full-offline** — the learner will do "very light" sessions (flashcard-level at most), not zero.

- **~Nov 1–7** (start of month) — eats the **last week of 1D DP** (1D DP runs Oct 12–Nov 8).
- **~Nov 24–30** (end of month) — eats a week of **2D DP** (2D DP runs Nov 9–Dec 6).

Both land **inside the DP phases** — the hardest, most interview-critical remaining DSA.

**Trajectory effect:** DP loses ~2 of its ~8 weeks → **DP completion slips ~Dec 6 → mid-to-late Dec**, and
"DSA reaches maintenance" (plus the *earliest* big-tech apply gate, which needs DP done) moves with it.
This is a **normal carry**, not a failure — the gate is state, not date ([[feedback_phase_dates_are_advisory]]).

**The load-bearing lever (this is the actionable part):** **do NOT teach a brand-new DP pattern in the 2–3
days before either break.** A just-taught pattern left untouched for a week is the exact
never-encoded → gap → 🔴-on-return failure ([[feedback_teach_then_measure]] logic). **Front-load new DP
right after returning; leave pre-break days for review/consolidation of already-seen patterns.**

**Re-entry:** the first 2–3 days back from each break run **review-heavy** (double warmups, backlog-recovery
style) to drain the spaced-rep bulge that accumulates while away. **cap-7** (raised Aug 6) is the drain
capacity that absorbs it; light maintenance during the weeks keeps the bulge small in the first place.

**Why this is a memory and also a study_guide note:** the constraint must fire at the **Oct/Nov weekly
builds**, months from now — so it's written into the DP phase table in `dsa/study_guide.md` (where the
builder looks) *and* here (so it surfaces in recall). See also [[project_interview_goal]] /
`career_strategy.md` for how the apply-gate slip is absorbed.
