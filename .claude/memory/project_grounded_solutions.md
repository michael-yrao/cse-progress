## The ask, and the reading of it that shaped everything

The learner: *"the visualization and the code on the site are no longer in sync … the code should
always be using code from cse-progress … pick one [version] that you feel has the best comments and
most easy to follow … do not modify it in any way … a link to where the problem came from … our
groundedness meter and it should always be 100%."* Then: *"hardcode to mine only as a gold
standard"* — the visualizer never renders another adopter's repo (a step generator is a hand-written
trace of ONE attempt, so `?repo=` is meaningless there; the progress dashboard keeps its `?repo=`).

**Why a method-level pick, not a file:** every attempt of a problem lives in one file as a dated
method (`floodFill_20260628`) or dated class (`StockSpanner_20260823`), 3–32 defs per file, order
not reliable. So the unit of "version" is a symbol, extracted with `ast`, byte-identical per line
(EOL-stripped — the working tree mixes CRLF/LF, GitHub serves LF), with real source line numbers so
the badge deep-links `blob/main/<file>#L<a>-L<b>`.

**Why content anchors, not line numbers:** the site's steps used hard-coded 1-based line numbers
into a pasted string; one added comment shifted every highlight below it. Steps now carry
`anchor: { match, nth?, to? }`, resolved against the live code at load time; an unresolvable anchor
is an ungrounded step and fails CI. **Groundedness** = every variant has a contract entry AND every
step anchor resolves to exactly one row (or an explicit `nth`).

## The judgement calls (the learner delegated the pick to the tech lead)

- 148 contract entries for 123 problems (95 visualized + 28 code-only added 2026-09-23): one entry
  per distinct approach the learner actually wrote.
  Three site variants had no learner counterpart and were removed: 76 Minimum Window Substring's
  only variant (the learner's file has `return "TBD"` and a method named Incorrect — the page is
  gone from the site), 219's HashMap variant, 141's Hash Set variant.
- Re-picked after review found the chosen code wrong: 1216 "manual memo" (`kPalindromeMemo` reads a
  memo it never writes) → the backtracking file's `kPalindrome`; 355 (`Twitter_20260626` reverses
  the popped list and returns the feed oldest-first) → the undated `Twitter`.
- Kept with an honest explanation on the page: 125 `isPalindrome` strips digits (`[^a-zA-Z]`),
  which LC counts as alphanumeric — the only correct alternative is an uncommented reverse-compare
  that isn't the two-pointer scan the page visualizes. **The learner may want to fix that attempt in
  the file; the site follows automatically** (pre-commit regenerates the contract; anchors resolve
  as long as the anchored lines keep their text).
- 15 3Sum uses `threeSumSet`; the no-set variant carries a suspect dedupe line (`k+=1` where `k-=1`
  is expected).
- Helper rule: a node class (`ListNode`/`TreeNode`/`Node`/`TrieNode_*`) is a helper segment only
  when the attempt CONSTRUCTS it, never for an annotation alone.

## Contract shape (v1) and the site's join

`{ key: "<lc>:<variant>", lcNumber, variant, title, url, file, symbol, attemptDate, segments:
[{ kind: container|attempt|helper, symbol, startLine, endLine, lines[] }] }`. The site's
`SolutionVariant.variant` joins by `${lcNumber}:${variant}`. Variant ids are kebab-case approach
names (`bfs`, `union-find`, `prims-heap`), never dates. `title` and `url` are nullable (a retired
problem with no header line has neither; the site falls back to a search URL).

## Big-O trainer contract (Sep 24)

A second contract, mirroring the one above: `dashboard/bigo.yml` (hand-curated pick + correct
time/space bounds) → `scripts/export_bigo.py` → `dashboard/big-o.json`, which the site's Big-O
Trainer deals from instead of its old hand-written 26-question paraphrase array. Same pick
mechanics as showcase (latest dated attempt, ties → lowest symbol in the file, an undated file
needs an explicit `symbol:`), plus a canonical label pool so the site can check an answer by exact
string equality against spellings the source material writes inconsistently (`O(m × n)`,
`O(V + E)`, `O(1) amortized`). `scripts/seed_bigo.py` seeded the manifest once from the site's own
per-problem `timeComplexity`/`spaceComplexity` metadata and its 26 existing question explanations,
so the learner didn't hand-write 130 entries — but every seeded bound is tagged "verify" and a
`TODO` bound is skipped (never emitted) until the learner fills it in as a rep. Decision record:
`decisions.yml` `bigo-contract`.
