**Set by the learner Jul 26, 2026:** *"the goal at end of each phase is that every single algorithm
should be locked down. If there is something slightly amiss, it is ok since we can't wait for every
problem to be retired to move on… but we should hold ourselves to a high standard, so knowing to
recognize these problems is important, so is the ability to execute them."*

**The standard:** at phase close, every **algorithm** in the phase must clear two axes:

| Axis | Evidence |
|---|---|
| **Recognition** — shape → algorithm + picking feature, cold, label stripped | a clean cold cue; no unresolved trigger in `recognition_gotchas.md` |
| **Execution** — writable from a blank page, correct, correct complexity | **≥1 problem for that algorithm at 🟢**, coded |

Both. Recognition without execution is knowing the thing's name; execution without recognition is a
solution waiting to be told which problem it belongs to. The interview grades recognition in the first
two minutes and execution for the next thirty.

**Why this replaces "every associated problem 🏆 Retired":** 🏆 needs streak 3 — a coded 🟢, then +30,
then +60, so **90+ days minimum per problem**. A phase runs ~3–5 weeks. The old rule was therefore
unmeetable by construction, which meant it was ignored rather than enforced — and an ignored gate is
worse than a loose one, because it makes the roadmap look governed when it isn't.

**Tolerance, and its limit.** A lingering 🟡 on the *second or third* problem of an algorithm that
already has a 🟢 is fine — don't stall a phase for it. **Not** fine: an algorithm with **zero** 🟢s, or
a recognition trigger still unresolved. That's an unlearned algorithm, not a rough edge.

**How to apply:**

1. **Report per algorithm at phase close, never per problem.** Eleven problems can look healthy while
   one algorithm is entirely unlearned — a per-problem count hides exactly what matters. Map the
   phase's problems onto its algorithms first, then grade each algorithm.
2. **Anything carried out must be scheduled in the same breath** — written into the next phase's
   warmup/review load with real slots ([[feedback_proactive_scheduling]], schedule-integrity rule). A
   carried gap that isn't slotted is a forgotten one, and this is the exact failure the tolerance
   clause could otherwise license.
3. This pairs with [[feedback_consolidation_reps]]: reaching ≥1 🟢 *and* solid recognition per
   algorithm is what the 3–4-problems-per-technique guidance is *for*. One problem can't establish
   recognition.
