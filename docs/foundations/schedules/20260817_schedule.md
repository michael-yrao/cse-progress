## ⚙️ Concept primer — Intervals + Greedy (Thu Aug 20)

**First run of the mechanism** added Aug 16 ([[feedback_concept_primer]]). ~15 min · **unrated** · no
tracker row · 2.0 units. It covers the **object** and its name, the **nearest neighbour** and the one
feature separating them, and **why the obvious approach is not enough** — then stops. The procedure is
the first rep.

| Primer | The object | The discriminator |
|---|---|---|
| **Intervals** | a `[start, end]` pair, and that **sorting turns overlap into a local check** — an all-pairs O(n²) comparison becomes one pass | **which key you sort by**: by *start* to merge, by *end* to schedule the most non-overlapping. Picking wrong is the entire difficulty, and it is invisible if the rule was memorised |
| **Greedy** | what makes a greedy choice **provably** correct — the exchange argument | **greedy vs DP.** Greedy commits and never revisits; DP weighs everything. The learner already holds this instinct from Dijkstra and Hierholzer, where *commit and never revisit* was load-bearing both times — naming it once should transfer |

⚠️ **The first Intervals problem must land at least a day later** (Aug 24, when the phase opens), exactly
like a teach. A primer measured in the same sitting measures nothing; what measures it is whether the
recognition call fires.

⭐ **1D DP opens Oct 12**, and Intervals/Greedy and DP are told apart by precisely the greedy-vs-DP
question. Teaching it as an object now is what makes the DP phase land. The exchange argument also
becomes `fundamentals/`'s third folder (**combinatorics**) — primers fill that folder rather than it
being a separate chore.
