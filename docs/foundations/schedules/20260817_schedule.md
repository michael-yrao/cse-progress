## 🔧 202 moved out of `dsa/probes/` — Fri Aug 21

**A probe that earns a tracker row stops being a probe**, and the directory split is what makes that
distinction mechanical: `dsa/probes/` sits outside `solutions.roots` precisely so *disposable* reps
never get discovered. 202 came back 🟡 on Aug 10, earned a row, and is now a normal review problem —
but its file was still in the probe directory, where **neither retry script can reach it**:

- `new_problem.py` resolves a retry to `<root>/<pattern>/<n>_*.py` and its twin check globs
  `<root>/*/<n>_*.py` — so it would have minted a **second** 202 file under `dsa/leetcode/` and forked
  the attempt history, the exact failure that check exists to prevent.
- `restore_history.py` keys a stash back by the same glob, so the stash would have been **orphaned** at
  session end (extracted, never restored).

`git mv dsa/probes/202_happy_number.py dsa/leetcode/graphs/202_happy_number.py`. No tracker change —
discovery matches on the number and the row already exists.

⭐ **Standing rule this establishes:** when a probe comes back 🟡/🔴, **move the file into
`dsa/leetcode/<pattern>/` in the same edit that adds its row.** Leaving it in `dsa/probes/` produces a
tracked problem whose retries cannot be scaffolded — silently, and only discovered at the next rep.
The one live case: **643** (Aug 19, 🟡 but the learner **overrode the row**) correctly stays a probe.
